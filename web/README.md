# PhysLog Web

iOS 版 PhysLog の Web 版（React + Vite + TypeScript）。
記録はブラウザの localStorage に保存する。同期（設定 → 同期）を始めたときだけ、サーバー（Supabase）にも保存する。

## 開発

```
cd web
npm install
npm run dev
```

## ビルド

- `npm run build` … `docs/app/` に出力（GitHub Pages で `/app/` として配信）
- `npm run build:single` … `dist-single/index.html` に1ファイル版（プレビュー共有用。初回は `src/seed.json` の記録入り）

## 同期と役割

- 同期は `src/lib/sync.ts`。グループごとに役割がある。
  - 管理者（owner）・指導者（coach）：グループ全員の記録を読み書きでき、本人を招ける。指導者を招く・人を外すのは管理者だけ。
  - 本人（client）：自分の記録だけを読み書きできる。抜けるときに、自分の記録をグループに残すか消すかを選べる。
- だれが何を読み書きできるかは、データベース側（RLS）で決まる。定義は `supabase/migrations/`。
- 人を招くときは、設定 → 同期 で招待コードを作る。コードは1回きり・期限つき（7日）。
- 記録の受け取りは、(更新時刻, コレクション, ID) の順に続きを取る（`pull_records`）。同じ時刻の記録が1000件の境目にあっても取りこぼさない。
- テスト（どちらも手元の Postgres を使う。本番には触れない）
  - `supabase/tests/run_local.sh` … マイグレーションを最初から流し、役割ごとの権限を確かめる
  - `node tests/sync-roles.test.mjs` … 同期のコードを、端末を何台か再現して通しで確かめる（先に `npm i --no-save pg`）

## iOS 版からの主な変更

- 「今日の記録」1画面に4カテゴリを集約。日付は ‹ › で移動
- コンディション（体調・睡眠）はシートを開かず1タップで保存
- トレーニングは「過去のメニューをコピー」、種目追加時に前回のセットを自動入力、±ボタンで重量2.5kg・回数1回刻み
- 種目の略称検索（BSQ → バックスクワット、BP、DL など）
- テキスト入力：「BSQ 20kg 5rep 1set, 60kg 5rep 3set」形式のメモを貼り付けて取り込み（略称・表記ゆれ・打ち間違いを推測、保存前の確認画面で修正、下書き自動保存、同じメモの二重取り込み防止）。実装は src/lib/quickParse.ts
- 各記録の編集画面で日付も変更可能
- トレーニング時間（開始・終了）とワークアウトタイマー（レスト／インターバル／ストップウォッチ）
- 体の写真（段階1）：IndexedDB に端末内保存、撮影日の体組成を実測／推定（前後の測定から補間、src/lib/estimate.ts）で表示、2日を並べて比較
- 記録する人を切り替え可能（コーチが複数人を記録する用途）
- グラフに「種目別の重量（最大／推定1RM）」を追加
- 移植済み：身体能力のPB判定、コンディション分析（相関）、メニュー提案、CSV書き出し、デモデータ
- 未移植：ジム設定、ヘルスケア・OCR取り込み、広告・課金
- 未着手：写真からの体組成推定（段階2、外部AIへの送信可否の判断待ち）、ランニング＋シューズ管理
